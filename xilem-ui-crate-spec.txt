## Overview

The services layer provides abstraction for external integrations including API communication, offline storage, federation, and cloud synchronization. All services use trait-based design for testability and flexibility.

## API Client Service

### ApiClientTrait

```rust

pub trait ApiClientTrait: Send + Sync {
    // Authentication
    async fn login(&self, username: String, password: String) -> Result<User>;
    async fn get_user_info(&self) -> Result<User>;

    async fn create_learner(&self, display_name: Option<String>) -> Result<serde_json::Value>;
    async fn get_learner(&self, learner_id: &str) -> Result<serde_json::Value>;
    
    // Session Management
    async fn create_session(&self, request: CreateSessionRequest) -> Result<Session>;
    async fn get_session(&self, session_id: &str) -> Result<Session>;
    async fn complete_session(&self, session_id: &str) -> Result<()>;
    
    // Task Responses
    async fn submit_response(&self, session_id: &str, request: SubmitResponseRequest) 
        -> Result<SubmitResponseResponse>;
    
    // Protocol Versioning
    async fn get_protocol_versions(&self, experiment_id: &str) -> Result<Vec<ProtocolVersion>>;
    async fn create_protocol_version(&self, experiment_id: &str, content: ProtocolContent) 
        -> Result<ProtocolVersion>;
    async fn compare_protocol_versions(&self, experiment_id: &str, from: &str, to: &str) 
        -> Result<ProtocolVersionDiff>;
}
```

### Database Schema

```sql
-- Sessions table
CREATE TABLE sessions (
    id TEXT PRIMARY KEY,
    learner_id TEXT NOT NULL,
    topology_type TEXT,
    start_time TIMESTAMP,
    end_time TIMESTAMP,
    status TEXT,
    data JSON,
    synced BOOLEAN DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Responses table
CREATE TABLE responses (
    id TEXT PRIMARY KEY,
    session_id TEXT NOT NULL,
    task_data JSON,
    user_answer TEXT,
    correct BOOLEAN,
    response_time_ms INTEGER,
    synced BOOLEAN DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (session_id) REFERENCES sessions(id)
);

-- Sync queue table
CREATE TABLE sync_queue (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    entity_type TEXT NOT NULL,
    entity_id TEXT NOT NULL,
    operation TEXT NOT NULL,
    data JSON,
    retry_count INTEGER DEFAULT 0,
    last_attempt TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- User preferences
CREATE TABLE preferences (
    key TEXT PRIMARY KEY,
    value JSON,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

   - Handle conflicts

## State Update Patterns

### Direct Mutations
Simple field updates in event handlers:
```rust
button("Click", |data: &mut AppData| {
    data.current_screen = Screen::Dashboard;
    data.success_message = Some("Navigated!".to_string());
})
```

### Flag-Based Async Handling
Pattern for async operations:

1. **Set flag**:
```rust
data.login_request_in_flight = true;
```

2. **Check in app_logic()**:
```rust
if data.login_request_in_flight {
    // Simulate async completion
    let result = perform_login();
    data.login_request_in_flight = false;
    data.current_user = Some(result);
}
```

3. **Update UI based on flag**:
```rust
if data.login_request_in_flight {
    label("Loading...")
} else {
    button("Login", |data| data.login())
}
```

### Complex State Transitions

#### Session Creation Flow
```rust
// 1. User triggers session start
data.create_session_in_flight = true;

// 2. app_logic() processes
if data.create_session_in_flight {
    // Create topology
    let topology = data.create_topology_for_domain();
    
    // Initialize core components
    data.task_generator = Some(TaskGenerator::new(topology.clone()));
    data.adaptive_scheduler = Some(AdaptiveScheduler::new(...));
    data.intervention_system = Some(InterventionSystem::new(...));
    
    // Create session
    data.current_session = Some(Session::new(...));
    
    // Clear flag
    data.create_session_in_flight = false;
    
    // Navigate
    data.current_screen = Screen::Training;
}
```

#### Task Submission Flow
```rust
// 1. User selects answer
data.selected_answer_index = Some(index);
data.submit_response_in_flight = true;

// 2. Process submission
if data.submit_response_in_flight {
    // Calculate metrics
    let response_time = data.task_start_time.elapsed();
    let correct = check_answer();
    
    // Update model
    data.current_learner.core_model.update(...);
    
    // Update metrics
    data.current_metrics.update(correct, response_time);
    
    // Store response
    data.session_responses.push(response);
    
    // Show feedback
    data.show_feedback = true;
    data.submit_response_in_flight = false;
}
```

```rust
// Trigger sync if online
if data.connectivity_monitor.is_online() {
    data.trigger_sync();
}
```

## State Validation

### Input Validation
```rust
impl AppData {
    pub fn validate_protocol_form(&self) -> Result<(), String> {
        // Validate numeric fields
        self.protocol_editor_target_n.parse::<usize>()
            .map_err(|_| "Invalid target N")?;
            
        // Validate ranges
        let power = self.protocol_editor_power.parse::<f64>()?;
        if power <= 0.0 || power > 1.0 {
            return Err("Power must be between 0 and 1");
        }
        
        // Validate required fields
        if self.protocol_editor_name.trim().is_empty() {
            return Err("Name is required");
        }
        
        Ok(())
    }
}
```

## Progressive Web App (PWA)

### Service Worker
Located at `src/service_worker.js`:

```javascript
// Cache strategies
const CACHE_NAME = 'abcdeez-v1';
const urlsToCache = [
    '/',
    '/offline.html',
    '/manifest.json',
    '/app.js',
    '/app.css'
];

// Install event
self.addEventListener('install', event => {
    event.waitUntil(
        caches.open(CACHE_NAME)
            .then(cache => cache.addAll(urlsToCache))
    );
});

// Fetch event with offline fallback
self.addEventListener('fetch', event => {
    event.respondWith(
        caches.match(event.request)
            .then(response => response || fetch(event.request))
            .catch(() => caches.match('/offline.html'))
    );
});
```

<file name="02_architecture.md"># Architecture Specification

## High-Level Architecture

### Design Patterns

#### Model-View-Update (MVU)
The application uses Xilem's MVU pattern:
- **Model**: `AppData` struct containing all application state
- **View**: `app_logic()` function producing widget trees
- **Update**: Event handlers modifying `AppData`

#### Offline-First
- All operations work offline by default
- Network requests are optional enhancements
- Local storage is source of truth
- Sync is eventual and automatic

#### Component-Based UI
- Reusable UI components in `components.rs`
- Screen modules for each major view
- Composable widget functions
- Consistent styling patterns

### Architectural Layers

```
┌─────────────────────────────────────┐
│         Presentation Layer          │
│  (Screens, Components, UI Logic)    │
├─────────────────────────────────────┤
│         Application Layer           │
│   (AppData, Business Logic)         │
├─────────────────────────────────────┤
│          Service Layer              │
│  (API, Storage, Federation)         │
├─────────────────────────────────────┤
│           Core Layer                │
│      (abcdeez-core library)         │
└─────────────────────────────────────┘
```

## State Management

### Central State (`AppData`)

The `AppData` struct is the single source of truth:


### State Update Patterns

#### Synchronous Updates
Direct field modifications in event handlers:

#### Asynchronous Operations
Flag-based async handling:
```rust
// Set flag
data.login_request_in_flight = true;

// In app_logic(), check flag and process
if data.login_request_in_flight {
    // Perform async operation
    // Update state when complete
    data.login_request_in_flight = false;
}
```

## lib.rs - Main Application Logic

### Entry Points

#### `run()` Function
```rust
pub fn run()
```
- Creates Xilem EventLoop with user events
- Initializes default AppData
- Creates Xilem application with app_logic
- Runs windowed application with title

#### `app_logic()` Function
```rust
fn app_logic(data: &mut AppData) -> impl WidgetView<AppData>
```
Main reactive UI function that:
1. Handles PWA initialization (WASM only)
2. Updates easter egg behavior
3. Processes async operation flags
4. Renders current screen based on state
5. Manages overlay components (demo, crab)

### Async Operation Handling

The app uses flag-based async handling pattern:
```rust
if data.login_request_in_flight {
    // Simulate completion
    data.login_request_in_flight = false;
    data.current_user = Some(user);
    data.current_screen = Screen::DomainSelection;
}
```

Flags processed:
- `login_request_in_flight`
- `create_session_in_flight`
- `submit_response_in_flight`
- `end_session_in_flight`
- `export_data_in_flight`
